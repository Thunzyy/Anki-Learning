# Illustration library and replacement

Open a deck and expand **Manage images**. Choose the current source (or all
images), the replacement source, and **Preview changes**. The preview shows
existing images, compatible replacements, and unmatched cards. **Apply to the
deck** processes that fixed selection in batches. You can stop after the current
batch. Missing matches and provider failures retain the current image.

The default uses existing files and makes no generation calls. Enable **Fetch /
generate missing images** to use Grok, Codex native image generation, or a supported stock provider.
This can consume provider credits or session quota. Gemini supports imported images.
Codex requires the official CLI with image generation support and a connected session;
its images retain source `openai` and origin `codex_cli`.
Provider replacement is strict: it never silently falls
back to a different source. Existing generated images can be replaced too.

## Context, not spelling

The active library does not reuse images using a bare word, a homonym, or a
comma-separated translation alias. It requires one of:

- A shared **meaning ID + scene ID**, independent of the source and translation
  languages. For example `bank:finance` + `deposit-cash` is distinct from
  `bank:river` + `walk-along-shore`.
- The same full translated meaning and full translated example, in the same
  translation language. Portuguese `banco` and English `bank` can therefore share
  an illustration when both represent the same French meaning and example.

This is conservative deterministic matching, not visual understanding or semantic
similarity search. Differently worded examples will not automatically match.
Generated images carry the context of their generation prompt; that is not a
guarantee of visual correctness. Historic images have **unverified context** and
are not silently assigned to new cards.

In the card editor, search **Contextual library** by word, meaning or filename.
Choose **Use for this context**, inspect the result and save. Alternatively, check
**Validate this image for the current meaning and example** on the current image.
This explicitly registers its context for future reuse. Meaning and scene IDs
allow sharing when the translated examples are in different languages. Editing
the meaning or example removes the old assignment unless you explicitly validate
the image again; its previous assignment remains in history.

## Provenance and history

Cards carry an asset ID, source, provenance, and replacement history. The library
stores SHA-256 for local files and available model/prompt/origin information.
Generated filenames are unique, so replacing an image does not overwrite another
card's original media. CSV exports include asset IDs and provenance.

`generated` means **historical AI image, provider unknown**. It does not mean Grok
or Gemini. Migration never infers a provider just from a local filename or the
current settings. You can correct a known provider in the card editor or import
an explicit manifest. Provider changes retain the previous assignment in history.

Each applied batch saves the original deck in `image-backups/<id>/` under the
application data directory. The SQLite library records operation events. These
local records are not uploaded to a provider. Restore a deck by stopping the app
and copying its saved JSON back to `decks/`; keep its referenced image files.

## Import images generated by a CLI

Create a JSON manifest next to the image files. Source and context are explicit:

```json
[
  {
    "path": "bank-deposit.png",
    "source": "grok",
    "model": "your-actual-model",
    "prompt": "The actual generation prompt, if available",
    "concept": "bank:finance",
    "scene": "deposit-cash"
  },
  {
    "path": "cat-sleeping.png",
    "source": "gemini",
    "word": "cat",
    "language": "en",
    "meaning": "chat",
    "example_translation": "Le chat dort sur le canapé.",
    "target_language": "fr"
  }
]
```

From `studio/api`, using the project's Python environment:

```sh
python -m app.image_operations --import-manifest /absolute/path/manifest.json
```

The importer validates all manifest rows before copying files, accepts PNG,
JPEG and WebP, and deduplicates by file content and declared source. It preserves
the original files. Manifest contexts are trusted declarations: review them.

## Retire Wikimedia throughout the local application

Stop the app and any generation CLI first. Use the same `LEARNING_DATA_DIR` as the
instance you want to migrate; the default is `studio/data`.

```sh
cd studio/api
python -m app.image_operations --remove-source wikimedia
python -m app.image_operations --remove-source wikimedia --apply
```

The first command previews the card counts. The second:

1. Backs up deck/cache JSON and an existing library database.
2. Registers historical assets without inventing provider or context metadata.
3. Retires Wikimedia library entries, clears their deck/cache assignments and
   keeps their history.
4. Quarantines identifiable local Wikimedia files that are not referenced by
   another source.
5. Persists a blocked-source policy so the app cannot fetch or reassign Wikimedia.

The backup directory contains `report.json` and any quarantined media. Restore
with the app stopped: restore deck/cache JSON, return quarantined files to their
original paths, and restore the saved SQLite database. If the migration created
the first library database, move it aside to return to the pre-migration state.

This affects the selected application's decks and caches. It cannot identify the
origin of files whose metadata was lost. It does not edit an installed Anki
collection, existing `.apkg` exports, remote releases, Docker volumes or another
computer. Re-export/sync the updated deck separately. Use one API process per data
directory and keep offline migrations/imports separate from active writers.

## API

- `GET /api/image-library`: source inventory, blocked providers and contextualized assets.
- `GET /api/image-library/assets?q=bank&source=grok&limit=24`: human-review candidates.
- `GET /api/decks/{id}/images`: source counts and per-card history.
- `POST /api/decks/{id}/images/replace`: preview by default; fields `source`,
  `destination`, `generate_missing`, `preview`, `ids`, `limit` (1–100, default 20),
  and `expected_revision` (use the revision returned by the preview/previous batch).
  Freeze preview IDs and batch them, as the interface does. Inspect `errors` and
  `changed` rather than assuming every selected card was replaced.

The former `cache/images.json` aliases remain for legacy inspection, not for
automatic contextual assignment. The active registry is `image-library.sqlite3`.

## Harmonize examples across languages

A shared scene is an explicit, reviewed teaching example. Translate its action
and objects naturally into each language, retain each card's target word and
meaning, and select an image that fits that scene. Similar spellings or French
glosses are only candidates: English `pie` and Spanish `pie` must stay separate.
An image caption or a language model's agreement is review evidence, not proof
that every visible detail is correct. Keep the evidence and uncertain cases.

Reviewed batches can be applied through an offline manifest:

```powershell
$env:PYTHONPATH = "studio/api"
python -m app.scene_harmonization manifest.json
# Stop the API and other writers before applying:
python -m app.scene_harmonization manifest.json --apply
```

The version-1 manifest has a `decks` array. Each entry contains `id`,
`expected_sha256` of the complete source deck JSON, and `updates`. Each update
contains a card `id`, a `fields` object (meaning, category, example, translation,
concept/scene IDs and image assignment), and, for a nonempty image,
`image_review: {"compatible": true, "method": "...", "sha256": "..."}`.

Preview validates every update, including target-word presence, sentence length,
image existence/digest, blocked sources and shared image consistency. It changes
neither decks nor registry. Apply backs up full original JSON, the manifest and
SQLite in `scene-backups/<id>/`, then writes through temporary files and records
assignment history. Unselected cards, vocabulary identities and word audio are
preserved. Exceptions roll back replaced decks and the registry; the journal
records completion or rollback. If the process itself is interrupted, stop the
API and restore all saved deck JSON plus the saved registry before retrying.
Regenerate separate sentence/cloze audio if such assets are used externally.

An explicitly reviewed accent repair can use a separate `word_correction`
object with `before_lemma`, `before_surface`, corrected `lemma` and `surface`,
and a nonempty `reason`. Original forms must match exactly, and only diacritic
changes are accepted. Cards with word audio are rejected unless a separate
`audio_review` explicitly confirms an orthography-only correction: status
`orthography_only_ipa_verified`, `pronunciation_unchanged: true`, matching
`expected_audio_url` and nonempty `expected_ipa`, and a nonempty linguistic
`reason`. This preserves the existing recording and IPA; it does not certify
the audio acoustically. The decision must be reviewed for each word, because
diacritics can change meaning or pronunciation. The original spelling and
review are retained in assignment history. Review IPA separately when accent
changes affect stress.

Run backend tests against isolated data, especially when production has a
blocked-source policy:

```powershell
$env:LEARNING_DATA_DIR = "$env:TEMP/learning-test-data"
python -m pytest studio/api/tests -q
```
